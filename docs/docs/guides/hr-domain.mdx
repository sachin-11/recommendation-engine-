# HR domain

Use this setup for job boards, applicant tracking systems and internal mobility: match a candidate's profile to open roles, show "similar jobs" on a job page, and power a semantic job search.

## Recommended domain config

```json
{
  "primary_embedding_field": "description",
  "searchable_fields": [
    "title",
    "description",
    "skills"
  ],
  "filter_fields": [
    "location",
    "experience_years",
    "job_type"
  ],
  "item_label": "job"
}
```

Register with it (or set it later on the dashboard's **Settings** page, or with `PUT /me/domain-config`):

```bash
curl -X POST $RECO_API/api/v1/auth/register -H "Content-Type: application/json" -d '{
  "name": "Acme", "email": "you@acme.com", "password": "a-strong-password",
  "domain_type": "HR",
  "domain_config": {"primary_embedding_field": "description", "searchable_fields": ["title", "description", "skills"], "filter_fields": ["location", "experience_years", "job_type"], "item_label": "job"}
}'
```

Why these fields:

- `description` is the richest text, so it is the primary field and leads the embedded text.
- `title` and `skills` are short but decisive; including them sharpens matches.
- `experience_years` is a number, so it supports range filters (`{"lte": 4}`).
- `location` and `job_type` are exact-match filters.

## Tips for better results

1. Write `description` as a paragraph about the work, not a list of perks. Perks, salary text and legal boilerplate dilute the embedding.
2. Send `skills` as a list. It is embedded as `skills: Python FastAPI …`, which matches skill-heavy queries and profiles well.
3. For candidate matching, use `/recommend/by-profile` with the candidate's skills and experience; profile field names do not have to match your item fields.
4. Upload `experience_years` as a number, not `"3+"`, or range filters will not match it.
5. Filter hard constraints (location, job type) instead of putting them in the query text.

More fields help only when they describe the item: every searchable field is part of the embedded text, so noisy fields (internal codes, boilerplate) make matches worse. After changing `searchable_fields` or `filter_fields`, run `POST /index/rebuild` so existing items are re-embedded.
