# Food domain

Use this setup for food delivery, restaurant menus and recipe apps: "more like this" on a dish page, craving search ("something spicy and cheesy"), and dietary-aware suggestions.

## Recommended domain config

```json
{
  "primary_embedding_field": "description",
  "searchable_fields": [
    "name",
    "description",
    "cuisine",
    "ingredients"
  ],
  "filter_fields": [
    "cuisine",
    "is_vegetarian",
    "price_range"
  ],
  "item_label": "dish"
}
```

Register with it (or set it later on the dashboard's **Settings** page, or with `PUT /me/domain-config`):

```bash
curl -X POST $RECO_API/api/v1/auth/register -H "Content-Type: application/json" -d '{
  "name": "Acme", "email": "you@acme.com", "password": "a-strong-password",
  "domain_type": "FOOD",
  "domain_config": {"primary_embedding_field": "description", "searchable_fields": ["name", "description", "cuisine", "ingredients"], "filter_fields": ["cuisine", "is_vegetarian", "price_range"], "item_label": "dish"}
}'
```

Why these fields:

- `description` carries taste and texture ("fiery", "creamy", "smoky"), which is what cravings are made of.
- `name`, `cuisine` and `ingredients` add strong signals for dish-to-dish similarity.
- `is_vegetarian` is a boolean filter; `price_range` and `cuisine` are exact or any-of filters.

## Tips for better results

1. Describe how a dish tastes, not just what it is: "smoky, charred, tangy" beats "paneer dish".
2. List `ingredients` so that allergy- and preference-driven queries ("no dairy", "garlic") have something to match.
3. Keep dietary rules as filters (`is_vegetarian: true`), never only as words in the query — similarity is not a guarantee.
4. Use `/recommend/by-item` on the dish page and `/recommend/by-text` for the search box.
5. Send `CLICK` and `PURCHASE` feedback from the menu; it is the data future ranking improvements are trained on.

More fields help only when they describe the item: every searchable field is part of the embedded text, so noisy fields (internal codes, boilerplate) make matches worse. After changing `searchable_fields` or `filter_fields`, run `POST /index/rebuild` so existing items are re-embedded.
