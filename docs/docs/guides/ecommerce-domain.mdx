# E-commerce domain

Use this setup for online stores and marketplaces: "customers also viewed" on product pages, natural-language search ("wireless headphones for the gym"), and budget-aware suggestions.

## Recommended domain config

```json
{
  "primary_embedding_field": "description",
  "searchable_fields": [
    "title",
    "description",
    "brand",
    "tags"
  ],
  "filter_fields": [
    "category",
    "brand",
    "price"
  ],
  "item_label": "product"
}
```

Register with it (or set it later on the dashboard's **Settings** page, or with `PUT /me/domain-config`):

```bash
curl -X POST $RECO_API/api/v1/auth/register -H "Content-Type: application/json" -d '{
  "name": "Acme", "email": "you@acme.com", "password": "a-strong-password",
  "domain_type": "ECOMMERCE",
  "domain_config": {"primary_embedding_field": "description", "searchable_fields": ["title", "description", "brand", "tags"], "filter_fields": ["category", "brand", "price"], "item_label": "product"}
}'
```

Why these fields:

- `description` explains what the product does; `title`, `brand` and `tags` add precise terms.
- `price` is a number (not a `$$` bucket), so shoppers can filter with `{"lte": 5000}`.
- `category` and `brand` are exact or any-of filters, e.g. `{"brand": ["JBL", "Sony"]}`.

## Tips for better results

1. Upload `price` as a number in one currency. Range filters compare numbers, so `"₹4,999"` would never match.
2. Put use-cases in `tags` (`gym`, `travel`, `gift`) — shoppers search by use more than by spec.
3. Restrict "similar products" to the same category with a filter when cross-category suggestions are unwanted (running shoes → a GPS watch can be a feature or a bug).
4. Re-upload products when price or stock changes; the same `external_id` updates in place. Out-of-stock items can be deleted or filtered with an `in_stock` filter field.
5. Batch several searches (e.g. per homepage row) with `/recommend/batch` — one request, one embedding call.

More fields help only when they describe the item: every searchable field is part of the embedded text, so noisy fields (internal codes, boilerplate) make matches worse. After changing `searchable_fields` or `filter_fields`, run `POST /index/rebuild` so existing items are re-embedded.
